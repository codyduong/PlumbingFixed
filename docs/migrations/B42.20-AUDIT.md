## Fork option (only if verdict is Fork)

Steam Workshop lets a mod "family" ship as more than one item, so a B42.19-targeting build
and a B42.20+-targeting build can coexist and be updated independently — that's the
mechanism referred to as "keeping them together, separated by version." Concretely, before
implementing, decide:

- **New Workshop item or reuse the existing one (3626008449)?** A second item needs its
  own id wired into `scripts/publish-workshop.*` / `mise.local.toml` alongside the current
  test/prod ids.
- **Repo layout for the fork point.** Options: a new versioned folder under
  `Contents/mods/PlumbingFixed/` (mirroring the existing `41/` stub pattern) vs. a long-lived
  git branch vs. a separate repo. Prefer whichever keeps the *shared* logic
  (`PFUtils.lua`, `DebugRig.lua`, docs) from forking if only the Java-interop layer diverged.
- **`workshop.vdf` handling.** Currently one VDF templated per publish target
  (test/prod); a second item needs its own content folder + VDF pair, not a third
  test/prod pair layered onto the same one.
- **Maintenance cost.** A fork means every future fix (e.g. a new landmine) potentially
  needs porting to both. Only take this path if reconciling truly isn't feasible — this is
  a structural decision to make deliberately, not a mechanical port.
